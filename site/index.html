Bakeoff

When several pull requests fix one issue, Bakeoff opens a Switch room for that issue

The Problem

Your maintainers spend days reading five or ten competing pull requests against a single issue. The winners get merged; the others get silence.

Bakeoff turns that into one sitting in one chat room: a matrix GitHub fills, two independent readings against the issue's checklist, questions to the contributors, one named maintainer picks the winner, it merges, and everyone else gets a note naming what they missed.

How It Works

1
Code Opens the Room
Bakeoff watches for multiple PRs on the same issue. When it finds them, it creates a Switch room with a contest matrix: one column per PR, all facts from GitHub.
2
Two Readers Read
Claude Code and OpenCode each read every diff against the issue's checklist. They record verdicts with file:line evidence. Code marks where they agree, split, or are waiting.
3
People Talk
Maintainers and contributors ask and answer in the room. A reader can re-read and record a new verdict. Questions get evidence, not opinion.
4
Maintainer Picks
A maintainer says @bakeoff-merge pick #N. The room shows an approval card. Nothing happens without a person.
5
It Lands on GitHub
The winning PR merges with a comment. Every other PR gets a thank-you note listing what it missed. The contest is decided once.

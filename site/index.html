A contest for pull requests

Bakeoff

When several pull requests fix one issue, Bakeoff opens a Switch room for that issue.

Two agents from different vendors check every PR against the issue’s own checklist. GitHub’s CI decides what passed. One named maintainer picks the winner before anything is posted.

The rules

Three decisions, kept separate.

Facts come from code. Checklist judgement comes from two independent readers. The winner comes from a person.

01

Code decides the facts.

CI, tests touched and files outside the issue’s scope come from GitHub. A red cell stays red; nobody in the room can overrule it.

02

Two readers decide the checklist.

Different vendors, separate readings. Agreement, split and still-waiting are marked by code, not by an agent’s confidence.

03

A maintainer decides the winner.

A named person allows the merge once. The room records who and when; a second pick is refused with the first decision.

The contest

Five moves, one sitting.

No re-reading pull requests for days. The whole contest runs in one room, in order.

  1. 01
    Intake

    Code opens the room.

    The watcher sees two or more PRs that say Closes #N and opens the Switch room bakeoff-N. The matrix is filled from GitHub: CI, tests touched, files outside scope.

  2. 02
    Checklist

    Two readers read.

    Claude Code and a second agent from another vendor read every diff against the issue’s Done-when list. Each item gets a verdict and file:line evidence.

  3. 03
    Discussion

    People talk.

    Maintainers and contributors ask and answer in the room. A reader can re-read a diff and record a new verdict without leaving the contest.

  4. 04
    Pick

    A maintainer picks.

    @bakeoff-merge pick #P. Switch shows an approval card in the room; a named maintainer allows it once. The merge agent cannot do this alone.

  5. 05
    Merge

    It lands on GitHub.

    PR #P is merged with a comment naming who picked it. Every other PR gets a thank-you that lists the checklist item it missed, then closes. A second pick is refused.

When it’s wrong

The room keeps the receipts.

Every contest is decided once, with the evidence still attached.

Claims pass · CI failed

The cell stays red.

merge_pick refuses a PR whose CI has not passed. Nobody in the room can overrule GitHub.

Readers disagree

The item is marked SPLIT.

Both verdicts stay visible with their evidence, so the maintainer sees exactly where to look.

A second pick

Refused, with the first name.

The room names who decided and when. Nothing else is posted to GitHub.
